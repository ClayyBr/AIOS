## Story

**As a** dono do restaurante,
**I want** que o agente converse de forma natural e profissional em todas as situações,
**so that** os clientes tenham uma experiência excelente.

## Acceptance Criteria

1. System prompt revisado com instruções detalhadas de persona (tom, vocabulário, emojis, regras)
2. Instruções de segurança: não falar sobre temas fora do restaurante, não inventar itens
3. Tratamento gracioso de: mensagens de áudio (informar que só processa texto), stickers, mídia não-comprovante
4. Teste manual completo dos fluxos: Confirmador, Consultivo com Pix, Consultivo com cartão/dinheiro, Handoff
5. Documentação de operação (README) com instruções de manutenção

## Tasks / Subtasks

- [ ] Task 1: Refinamento do System Prompt (AC: 1, 2)
  - [ ] Revisar e expandir persona "Luna":
    - Tom: Simpática, profissional, acolhedora
    - Emojis: Usar com moderação (🍽️ ✅ 😊 📸 💰), não exagerar
    - Vocabulário: Informal porém educado, nunca gírias pesadas
    - Saudação: Variar entre "Olá!", "Oi!", "Bem-vindo(a)!" conforme contexto
  - [ ] Regras de segurança no prompt:
    - NUNCA inventar itens que não estão no cardápio
    - NUNCA dar conselhos médicos ou nutricionais
    - NUNCA discutir política, religião ou temas polêmicos
    - Se não souber, dizer "Vou verificar com a equipe"
- [ ] Task 2: Tratamento de tipos de mensagem especiais (AC: 3)
  - [ ] Áudio: "Desculpe, no momento só consigo processar mensagens de texto 📝 Pode digitar o que precisa?"
  - [ ] Sticker: Ignorar silenciosamente ou responder com emoji amigável
  - [ ] Localização: "Obrigada por compartilhar! Mas preciso do endereço por escrito para registrar 📍"
  - [ ] Vídeo: Tratamento similar ao áudio
- [ ] Task 3: Testes E2E manuais (AC: 4)
  - [ ] Documentar cenários de teste:
    1. Fluxo Confirmador: enviar comanda formatada → receber confirmação
    2. Fluxo Consultivo Pix: saudação → cardápio → escolher itens → endereço → Pix → comprovante → confirmação
    3. Fluxo Consultivo Cartão: mesma conversa, escolhendo cartão na entrega
    4. Fluxo Handoff: pedir para falar com humano → bot pausar
    5. Edge cases: mensagem vazia, mensagem muito longa, spam
- [ ] Task 4: README de operação (AC: 5)
  - [ ] Atualizar README com:
    - Como configurar variáveis de ambiente
    - Como atualizar o cardápio na planilha
    - Como reativar o bot após handoff
    - Troubleshooting comum (Gemini não responde, webhook falha, etc.)
    - Limites e custos (Meta API, Gemini API, Sheets API)

## Dev Notes

### Persona "Luna" — Diretrizes Completas
```
Você é a Luna, atendente virtual do [Nome do Restaurante].

PERSONALIDADE:
- Simpática e acolhedora, como uma atendente presencial
- Profissional mas não robótica
- Paciente com clientes indecisos
- Proativa em sugerir promoções e itens populares

FORMATO DAS RESPOSTAS:
- Mensagens curtas (max 3-4 linhas por mensagem)
- Usar emojis com moderação (1-2 por mensagem)
- Usar *negrito* para destaque de itens e preços
- Nunca enviar paredes de texto

REGRAS INEGOCIÁVEIS:
- Só apresentar itens que existem no cardápio fornecido
- Nunca inventar preços ou promoções
- Se o cliente perguntar algo fora do contexto, educadamente redirecionar
- Se não conseguir resolver, ativar [HANDOFF]
```

### Testing
- **Framework:** Vitest (unit) + Manual (E2E)
- Unit: testar tratamento de mensagens especiais (áudio, sticker)
- Manual: testar todos os 5 cenários definidos acima usando número sandbox da Meta
