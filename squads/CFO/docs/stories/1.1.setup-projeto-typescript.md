## Story

**As a** desenvolvedor,
**I want** um projeto Node.js/TypeScript configurado com Express e estrutura de pastas padronizada,
**so that** tenha a base de código pronta para desenvolvimento do agente atendente.

## Acceptance Criteria

1. Projeto inicializado com `package.json`, `tsconfig.json`, e scripts de dev/build/start
2. Express configurado com endpoint `GET /health` retornando `{ status: "ok", timestamp: ... }`
3. Variáveis de ambiente carregadas via `dotenv` com arquivo `.env.example` documentado
4. Estrutura de pastas: `src/`, `src/routes/`, `src/services/`, `src/controllers/`, `src/config/`, `src/types/`, `src/utils/`, `src/prompts/`
5. ESLint e Prettier configurados
6. `.gitignore` configurado (node_modules, .env, dist/)

## Tasks / Subtasks

- [ ] Task 1: Inicializar projeto Node.js (AC: 1)
  - [ ] Criar `package.json` com name, version, scripts (dev, build, start, lint, format, test)
  - [ ] Configurar `tsconfig.json` com `strict: true`, `outDir: dist`, path aliases `@/*`
  - [ ] Instalar dependências: `express`, `dotenv`, `pino`, `zod`, `@google/generative-ai`, `googleapis`
  - [ ] Instalar dev dependencies: `typescript`, `tsx`, `@types/express`, `@types/node`, `eslint`, `prettier`, `vitest`
- [ ] Task 2: Criar estrutura de pastas (AC: 4)
  - [ ] Criar `src/config/`, `src/controllers/`, `src/routes/`, `src/services/`, `src/types/`, `src/utils/`, `src/prompts/`
  - [ ] Criar `tests/unit/`, `tests/integration/`, `tests/fixtures/`
- [ ] Task 3: Configurar Express e Health Check (AC: 2)
  - [ ] Criar `src/app.ts` com Express setup e middlewares (json parser, cors)
  - [ ] Criar `src/server.ts` como entry point (listen na PORT)
  - [ ] Criar `src/routes/webhook.ts` com `GET /health`
- [ ] Task 4: Configurar variáveis de ambiente (AC: 3)
  - [ ] Criar `src/config/env.ts` com validação via zod
  - [ ] Criar `.env.example` com todas as variáveis documentadas
- [ ] Task 5: Configurar ferramentas de qualidade (AC: 5, 6)
  - [ ] Criar `.eslintrc.json`
  - [ ] Criar `.prettierrc`
  - [ ] Criar `.gitignore`

### Padrões de Código (Architecture)
- **Imports:** Sempre absolutos com `@/` prefix
- **Naming:** Arquivos kebab-case, classes PascalCase, funções camelCase
- **Logging:** Usar pino, NUNCA `console.log`
- **Sem `any`:** Usar tipos explícitos

### Testing
- **Framework:** Vitest
- **Localização:** `tests/unit/`, `tests/integration/`
- **Naming:** `*.test.ts`
- Nesta story: testar apenas endpoint `/health`
