## Story

**As a** cliente,
**I want** fazer meu pedido conversando naturalmente com a atendente pelo WhatsApp,
**so that** tenha uma experiência personalizada e tire dúvidas sobre o cardápio.

## Acceptance Criteria

1. Agente apresenta o cardápio de forma amigável quando solicitado
2. Agente sugere promoções do dia proativamente
3. Agente coleta itens do pedido com opções/adicionais conforme o cardápio
4. Agente solicita endereço de entrega
5. Agente pergunta forma de pagamento (Pix, cartão na entrega, dinheiro)
6. Agente gera resumo formatado do pedido no padrão de comanda para confirmação do cliente
7. Após confirmação, registra na Google Sheets de pedidos

  - [ ] Integrar `SessionManager` com `GeminiService`: incluir estado da sessão no contexto

- [ ] Task 3: Coleta de endereço e pagamento (AC: 4, 5)

## Dev Notes

### Abordagem de Extração de Dados
O Gemini receberá instruções no system prompt para formatar dados estruturados em um padrão detectável:
```
Quando o cliente confirmar um item, inclua na resposta a tag:
[ITEM_ADDED: {"name": "Dog Super", "quantity": 1, "price": 22.00}]

Quando coletar o endereço:
[ADDRESS: "Rua da Constituição 171, Morumby"]

Quando coletar o pagamento:
[PAYMENT: "Pix"]
```

O `MessageController` parseia essas tags da resposta do Gemini e atualiza a sessão.
A tag é removida antes de enviar a mensagem ao cliente.

### Alternativa (mais simples para MVP)
Deixar o Gemini conduzir a conversa livremente e, ao final, pedir que o Gemini gere a comanda formatada.
O `OrderService` parseia a comanda gerada pelo Gemini (reusa o parser da Story 3.2).

### Testing

- Testar `buildOrderFromSession()` com sessão completa
